# T-057 — сквозной сценарий Diary → Kafka → Profile

Модуль проверяет AddMeal через действующий RPC `DiaryService.AddEntry`. Diary и Profile запускаются из настоящих bootJar в отдельных JVM. PostgreSQL 17 (отдельные diary_db/profile_db), Kafka и Schema Registry запускаются Testcontainers. Рабочий Compose, Redis и Keycloak не используются.

## Запуск

Нужны JDK 21, работающий Docker и доступные образы контейнеров. Из корня проекта:

```bash
./gradlew -PbackendOnly=true :backend:integration-tests:test
```

Gradle автоматически собирает оба bootJar и генерирует gRPC-клиенты из существующих Proto. Контракты и миграции не копируются и не изменяются. Готовый профиль с целью 2000 ккал создаётся SQL-фикстурой после штатных Liquibase-миграций; авторизованное чтение остатка не использует Redis. Тестируются доверенные gRPC-заголовки внутри серверного контура; Envoy/JWT и мобильная синхронизация не входят в этот сценарий.

## Проверяемые гарантии

- AddEntry с 350 ккал проходит через настоящие транзакцию Diary, автоматический outbox scheduler, Avro/Schema Registry, Kafka и consumer Profile. GetDailyCaloriesBalance возвращает 350 потреблённых и 1650 оставшихся ккал.
- Проверяются поля фактического Avro-события, регистрация subject, статус PUBLISHED и строки в обеих БД.
- Повтор идентичного запроса с прежним ключом возвращает тот же ответ без новых diary_entries, idempotency_keys и outbox_messages.
- Четыре конкурентных повтора создают одну запись и один outbox.
- Повторная публикация фактического события Diary не создаёт второй processed_events и не меняет остаток. Проверка выполняется после продвижения committed offset группы Profile за повторно отправленную запись.
- Изменённый запрос с прежним ключом отклоняется ALREADY_EXISTS; новая запись с новым ключом учитывается независимо.

Доставка outbox — at least once. Уникальность пользовательского эффекта обеспечивает дедупликация Profile по пользователю и записи. Проверяется серверная проекция калорий; денежный остаток, локальные PENDING и компенсация удалений в этот контракт не входят.

## Ограничения времени и диагностика

Ожидания ограничены: старт PostgreSQL/Kafka до 45 секунд на контейнер, Schema Registry до 60 секунд, готовность JVM до 45 секунд, сценарий до 60 секунд, задача Gradle test до 5 минут. RPC имеют deadlines, ожидание асинхронной обработки выполняется Awaitility без Thread.sleep. Первое скачивание зависимостей и образов может потребовать дополнительного времени вне этих ожиданий.

JUnit-отчёты: `build/reports/tests/test/`, XML: `build/test-results/test/`. Логи приложений: `build/service-logs/diary.log` и `profile.log`. Инфраструктура и процессы закрываются после тестов и при ошибке запуска. В CI отчёты и логи сохраняются как artifact; сценарий запускается отдельно от обычных backend-тестов.
